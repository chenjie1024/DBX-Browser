# DBX 网页阅读（DBX Web Reader）

在 DBX 里打开任意网站：Rust Sidecar 代替浏览器沙箱去抓取页面，抽取正文、清掉脚本与广告，
再按「站点规则」重排成干净的阅读视图。抖音、小红书、知乎、B 站这类站点有内置规则，
小说站会自动识别上一章 / 下一章，所有站点都可以自己调字体、字号、行距、配色，甚至写自定义 CSS。

```
com.dbx.webview   0.7.0   windows-x64
```

## 它为什么需要原生 Sidecar

DBX 的插件 UI 运行在 `sandbox="allow-scripts"` 的 iframe 里：源是 opaque、没有网络、拿不到父页面
DOM。这也意味着插件**不能**直接把 `https://www.douyin.com` 塞进一个 `<iframe>` —— 目标站点的
`X-Frame-Options` / `frame-ancestors` 会拒绝被嵌套，即使嵌套成功也无法注入样式。

所以真正的抓取与清洗放在 Rust Sidecar 里完成（它不受浏览器 CSP / CORS 约束），UI 只负责渲染
Sidecar 返回的、已经净化的 HTML 片段。代价要说清楚：**正文由 JavaScript 渲染的页面拿不到内容**，
插件会明确提示「该页面正文由 JavaScript 渲染」，而不是显示一片空白。

## 功能

- **插件内实时页面（WebView2）**：小红书这类服务端只返回空壳、正文和评论全靠 JavaScript
  渲染的站点，现在可以在**插件面板里**直接看、直接点、直接登录和评论。实现方式不是 iframe，
  而是 sidecar 起一个屏幕外的 WebView2（真实的 Chromium/Edge 内核），用
  `Page.startScreencast` 把画面帧送到 UI，再把鼠标/滚轮/键盘/中文输入通过
  `Input.*` 送回去。登录 profile 落盘，扫一次码以后一直有效。
  - 地址栏、后退/前进/刷新、标签页都照常可用；点小红书笔记会正常进入详情页。
  - 画面上点击后可直接打字；中文输入法照常用（隐藏的输入区承接 IME，再用
    `Input.insertText` 写进页面），Ctrl+A/C/V、回车、退格、方向键也会转发。
  - `实时页面` 按钮可手动切换；小红书地址会自动进入实时页面。切走标签页 / 伪装界面 /
    窗口不可见时会暂停推帧，回来继续。
- **任意网址**：地址栏输入域名即可（自动补 `https://`）；不是域名时按 `general` 规则做搜索。
- **三种模式**
  - `阅读模式`：抽取正文容器并输出干净排版，适合文章、小说章节。
  - `整页模式`：保留整页结构，只做安全清理与链接/图片地址绝对化。
  - `源码模式`：查看清理后的 HTML 源码。
- **导航页照常渲染，链接可点**：首页 / 频道页 / 列表页本身没有正文，但它们的价值就在链接本身。
  插件会**正常渲染**这些页面（加上一套"导航列表"排版，免得一屏裸链接看着像界面坏了），并在提示栏
  说明一句。实测：笔趣阁首页 → 点书 → 目录页（204 章）→ 点章节 → 正文，全程在插件内完成。
- **链接必须被拦截，否则界面会被"吃掉"**：这是本插件最严重的一个坑。正文里的 `<a>` 如果按
  浏览器默认行为处理，**iframe 会自己导航到那个网址** —— 插件界面（工具栏、热键）整个消失，
  只剩一个裸网页，而且无法用代码退回（我们的 JS 已经不在了）。真实站点大量写成
  `<a><span>下一章</span></a>` / `<a><img></a>`，所以：
  1. 用 `closest("a[href]")` 向上找锚点，不能只判断 `event.target.tagName === "A"`；
  2. 挂在 `document` 的**捕获阶段**，任何链接都跑不掉；
  3. 只要点在链接上就先 `preventDefault()`（mailto/下载/未知协议也一样），中键 `auxclick` 同样拦；
  4. 结构性防线：渲染后给正文所有外链加 `target="_blank"`——沙箱没有 `allow-popups`，
     默认点击会被浏览器拦掉，即使守卫漏了也只会"点了没反应"，不会销毁界面。
  实测：锚点包 span、锚点包 img、mailto、中键点击，四种情况 iframe 都没有离开。
- **目录按钮**：章节页会自动找出这本书的目录地址（优先用页面自己的"目录/书架"链接，找不到就按
  URL 形状推），地址栏右边出现「目录」按钮，一键跳回目录。
- **合并分页会智能拼接断句**：小说站经常在句子中间切页（上一页结尾"他抬起"、下一页开头"头来"）。
  这种情况**直接接上、不插分隔符**；只有上一页确实收了尾（句末标点）才插一条虚线分隔。
- **要登录的站点会直接给下一步**：实测确认章节页需要登录/cookie 才给正文的大平台（阅文系、
  纵横、17K、起点、晋江等），插件不再只提示"内容太短"，而是给一条**不自动消失**的提示条
  「这个站要登录才给正文」+ 一个「用浏览器窗口打开」按钮。
- **提示 3 秒自动收掉**：顶部警告条（"已合并 N 个分页"这类）和状态栏提示都会在 3 秒后自动隐藏，
  不再占着正文位置；需要用户动手的那条提示不会自动消失。
- **设置抽屉分三个页签**（工具栏那个「设置」按钮打开）：
  | 页签 | 内容 |
  |---|---|
  | **Aa 样式** | 仅当前站点、字体、字号、行高、页面宽度、正文宽度、文字/背景色、跟随主题、段间距、字间距、首行缩进、夜间模式、自定义 CSS（含实时校验） |
  | **◎ 浏览器窗口** | 用浏览器窗口打开当前页面、取回浏览器窗口的当前地址（含最近访问清单）、profile 路径 |
  | **⚙ 设置** | 外观（日间/夜间/跟随）、切换热键、打开工作台时先显示、切回 DBX 时自动显示、离开工作台时自动显示、合并分页、繁体转简体、版本号 |底部「恢复默认」只在「样式」页签显示。
- **用浏览器窗口打开**：地址栏右边的「浏览器打开」按钮会拉起系统 Chrome / Edge，开一个独立
  profile 的阅读窗口，看到的是**真实渲染**的页面（视频可播、可登录），当前阅读样式会一并写进
  那个窗口。这是唯一能看「活的页面」的方式 —— 插件沙箱内嵌不了外部站点。
  - 工具提示与样式面板底部都会写明**将要打开的地址**。注意 `--app` 窗口的标题栏显示的是
    **网页标题**（浏览器行为），不是网址，所以网址在打开前先告诉你。
  - `--app` 模式下**没有地址栏**（这是刻意的，看起来才像个阅读窗口）。想复制或改写网址，
    用地址栏右边的一键按钮：它会把当前网址填回地址栏并全选，可直接 Ctrl+C。
  - **「取回浏览器窗口的当前地址」**：在阅读窗口里点到哪一页，点这个按钮就把那一页取回插件里
    继续读（地址栏会同步填上）。取回后还会**列出最近 10 条访问记录**——在窗口里连翻几页之后，
    想回去的往往是其中某一页，点哪条开哪条。实现方式见下。
- **站点规则（12 条内置预设）**：小说 / 社交 / 视频 / 社区 / 资讯 / 技术 / 百科 / 通用。
  按域名匹配，支持 `example.com`、`*.example.com`、`bqg*` 前缀通配与 `example.com/path` 路径前缀。
  其中 `novel-obfuscated` 专门针对**类名被随机化**的小说站（每次请求都换 class 名的那种），
  这类站点无法用选择器写规则，改为按结构（`article` / `main`）与内容特征识别。
  - **抖音 / 红果短剧**（`douyin`、`hongguo`）已加入预设。这两站几乎全靠前端渲染，服务端常只拿到
    验证码页；界面**不再**挂「建议用实时页面」之类的提示，点工具栏的「实时页面」即可。
  - 「政府与文档」已移除（政策类页面用「通用网页」即可）。
- **自定义站点预设**：侧栏「站点预设 → ＋ 新建」可以加自己的规则（名称 / 分类 / 域名 /
  正文选择器 / 删除选择器 / 搜索地址 / 渲染模式），保存后立刻生效。
  自己建的规则可以「编辑 / 删除」，内置规则只读。
  - 域名与选择器选择遵循与内置规则相同的语义（`*.`、后缀、`bqg*` 前缀、`host/path`）。
  - 自定义规则排在**内置规则前面**，所以同名域名会优先命中你的规则。
  - 规则存在 sidecar 数据目录的 `settings.json` 里，重装插件不丢。
- **域名标签的右键菜单**：预设下面每个域名标签是「点一下打开该站点」，**右键**弹出菜单：
  - **修改**：改这一条域名。自定义预设直接改自己的规则；内置预设改不了本体，所以做法是
    「屏蔽旧域名 + 按原选择器复制一条用户规则到新域名」（名字带「（副本）」后缀，避免和内置那条重名）。
  - **删除**：会先变成「确认删除 xxx？」再点一次才生效（插件 sandbox 里没有 `confirm()`，
    所以这个二次确认是自己画的）。
    - 自定义预设：直接从规则里删掉该域名；域名删光的规则整条消失（不留死规则）。
    - 内置预设：记入 `blockedHosts`，域名以**灰色删除线**保留，右键 → **恢复** 可以撤回来。
  - 两个坑记在这里：① 灰色标签**不能用 `disabled`**（禁用按钮不派发 `contextmenu`，
    右键恢复永远点不到），改用 `data-off` + 样式；② `customRules` 和 `blockedHosts`
    必须**一起**提交，只发前者会把屏蔽列表覆盖成空，用户删掉的域名会自己回来。
- **预设匹配在 UI 与 sidecar 两侧必须一致**：UI 用 `presetForUrl()` 决定列表高亮和
  `tab.presetId`，sidecar 用 `match_rule()` 真正选规则。两边语义一旦不同，就会出现
  「后端匹配到了、界面却显示通用网页」。修过一个真实案例：UI 拿 `host`（**带端口**）
  去比 `127.0.0.1`，永远匹配不上；现在统一用 `hostname`，并补齐了前缀通配与路径前缀。
- **预设列表里的域名可以点**：点一下就打开该站点。鼠标悬停显示完整地址。点预设本身的名称则是
  「把这条规则套用到当前页面」，会重新解析一次（服务端按 presetId 选规则与排版）。
- **导航墙识别**：首页 / 频道页 / 列表页本身没有正文，抓到的只是一堆链接。这种情况会明确提示
  「这一页只有导航链接」并给出换详情页的建议，而不是把一屏链接倒给用户。
- **章节目录自动识别**：不依赖 class 名，而是找「一组 URL 形状相同、标题互不相同的链接」。
  小说站门槛 5 条、其它站点 15 条，避免把新闻页的「相关阅读」误判成目录。
- **章节导航**：识别「上一章 / 下一章」；书籍目录页则给出「开始阅读」入口，点一下直接进第一章。
- **合并分页（默认开）**：中文小说站常把一章切成 `_1.html`、`_2.html`… 插件会自动把后续页抓回来
  拼成完整一章，读完再进下一章。设置里可以关掉。
- **预取下一章**：当前章读完后台就把下一章取回来，点「下一章」几乎瞬时切换。
- **续读**：按地址记住滚动位置，下次打开同一章直接回到上次读到的地方。
- **本地 txt 小说**：入口在侧栏「本地小说 → 导入 txt」（工具栏不再占位）。插件在本机读出来、
  按章节切开，之后完全离线阅读。
  - **书架**：导入的书都留在书架里（最多 6 本），点哪本读哪本，可单独移除；
    重新导入同名文件会替换而不是重复。以前只能存一本，第二本会把第一本冲掉。
  - **浏览记录**：记录每本书读到第几章，一键回去继续；读过的书同时记住各自的位置
    （实测：A 书在第 30 章、B 书在第 5 章，来回切换都回到原处）。
  - **章节识别**覆盖常见写法：`第123章` / `第0001章` / `第十二回` / `第 N 节` /
    `Chapter 12` / `卷一` / `序章·楔子·番外·大结局`。
  - **编码自适应**：先按严格 UTF-8 试解，失败退回 GB18030。中文小说 txt 有大量 GBK 老资源，
    不做这一步会直接读成乱码（实测那本 8.9 MB 的就是 GBK）。
  - **目录可点**：侧栏列出全部章节（当前章高亮并自动滚到可见处），点哪章读哪章；
    正文上方还有章节下拉、`‹ 上一章` / `下一章 ›`（中间显示「第 n / m 章」）。
  - **目录虚拟滚动**：合订本动辄两千多章，全量渲染会卡在打开目录那一刻。现在只渲染
    「可视窗口 + 上下各 8 行余量」，用上下两条占位 `<li>` 撑出总高度：
    | 场景 | 全量渲染（实测） | 虚拟滚动（实测） |
    |---|---|---|
    | 673 章 | 92.8 ms | 约 4.6 ms（33 行窗口） |
    | 2048 章 | 267.1 ms | 4.6 ms（同样几十行） |

    实现要点（三个坑）：
    1. 行高用 `getBoundingClientRect().height` 取**小数**——`offsetHeight` 会取整，
       673 行 × 0.95px 的误差累积下来接近 30px，滚到后面会跳一下；
    2. 卷首行原来靠 `margin + border + padding` 拉开间距，会破坏"等高"，前缀和算出的
       偏移就越来越歪。虚拟模式改用等高变体 `.lb__item--volume-start--flat`，
       分隔线用**背景渐变**画 1px（`border` 会把行撑高 1px）；
    3. 少于 300 章不启用虚拟化（一次渲染几十上百行本来就快，虚拟化反而多一处出错的地方）。
  - **目录滚动时只重建视窗**：`scrollTop` → 二分查找起始下标（前缀和数组），
    重建十几到几十个节点；窗口没变就直接 return，不做任何 DOM 操作。
  - **阅读样式全部适用**：字体、字号、行高、页宽、配色、繁简转换、伪装热键都与网页阅读共用同一套设置。
  - **分卷自动识别 + 跨卷连读**：一部小说被切成 `书名_1.txt` / `_2` / `_3`（也认
    `上/中/下`、`第N卷`、`Part 2`）时，会**折成书架里的一条**，目录是全书连续的章表，
    读到第 1 卷最后一章点「下一章」直接进第 2 卷。实测三卷 673+684+691 = **2048 章**，
    章号连续、卷交界处有分隔标签、正文上方显示「第 n/2048 章 · 第 2/3 卷」。
    - 判据是**文件名**：去掉卷号记号后基名相同才算同一系列。宁可漏判也不要把两本
      不相干的书并成一本。
    - **缺卷不阻断**：某一卷的文件丢了，其余各卷照常可读，只提示缺了几卷。
    - 正文按卷懒加载（打开哪卷取哪卷），书架条目上会显示「已载入 2/3 卷」，也可以一次
      把其余各卷载入。
  - **读完标记**：读到最后一章的卷/书会显示「读完」角标。
  - **本地书也能收藏**：⭐ 收藏的是「这本书的这一章」，出现在侧栏「书签」里，
    点了直接跳回那一章。（以前本地书没有网址，收藏按钮对它完全无效。）
  - 文字只在内存与 sidecar 数据目录里，**不上传、不联网**；单本上限 48 MiB（约 2400 万字）。
  - **存储架构（重要）**：正文**不能**放在 UI 的 `host.storage` 里 —— 宿主对它有硬限制
    （单值 256 KiB、插件总量 1 MiB），一本小说就把整条记录顶爆，表现就是"关掉 DBX 再打开
    书架空了"。所以：
    | 数据 | 存放位置 | 限制 |
    |---|---|---|
    | 书架索引（书名/章节数/字数）、阅读位置、其它设置 | 宿主 `storage` | 256 KiB/值，够用 |
    | 小说原文 | sidecar `DBX_PLUGIN_DATA_DIR/local-books/` | 只受磁盘限制 |
    原文按需取回（打开哪本取哪本），并在磁盘上以 id 的哈希命名，UI 传什么 id 都不会
    变成路径穿越。
  - **书架索引读回后必须立刻重画侧栏面板**：索引一直都在 storage 里，但少了这次渲染，
    界面就是空的，看起来像"数据没存住"——重新导入一次才顺带画出来。这是踩过的坑。
  - **大文件走分块**：UI ↔ 宿主的 JSON 桥单次参数上限 2 MiB，4.5 MB 的 txt 整本发过去
    会被宿主直接拒掉（HTTP 400）。所以按 25 万字符一块、逐块 append，最后校验**字节数**。
    实测 4.5 MB / 152 万字符 → 7 块，落盘内容与原文逐字节一致。
    换行在导入时统一成 `\n`：宿主的 RPC 会归一化换行，若某块正好切在 `\r\n` 中间就会丢字节。
- **伪装界面默认就有数据**：结果区一进来是 14 行（不是 0 行）。顶部「检索」框按关键字过滤，
  「数据库」下拉在同表的三个分区之间切换 —— **切到哪个分区都有数据**，不会出现空表。
  结果区支持复制与「导出 CSV」（沙箱没有下载通道，所以是复制到剪贴板）。
- **繁简转换（内置字库，默认开启）**：2797 个繁→简单字 + 1261 条词组映射，不联网。
  字库**内联在 `ui/index.html` 的惰性 JSON 数据岛**里（`#trad2simpData`），
  由 `app.js` 读取后按"首字索引 + 最长匹配"扫描转换。
  转换算法与数据源逐条比对过：2797 个单字 + 1261 条词组全部一致（`tools/verify-trad2simp-inline.mjs`）。
  - 为什么不用外部 `ui/trad2simp.js`：真实 DBX 宿主里那个脚本**没有被执行**，
    反而把整段 JS 源码当文本渲染到了界面上（用户截图确认）。数据内联后既没有那次外部
    请求，宿主也无从"显示"它。源文件移到 `tools/trad2simp-tables.js`，只作构建输入、不参与打包。
  **2797 个繁→简单字 + 1261 条词组映射**。打开繁体源的小说站不用先找开关，默认就是简体；
  想读原文可以在「设置 → 繁体转简体」里关掉，关掉的选择会记住。
  只处理文本节点，不碰标签与属性；映射表缺失时这个开关会自动隐藏而不是留着装样子。
  常用字的覆盖面是实测过的：任意一段台湾/香港小说正文转换后不应残留繁体字。
- **正文解包**：识别两类常见混淆——
  - 中文小说站的 `document.writeln(qsbs.bb('<base64>'))`；
  - Next.js / Nuxt 等站点的 `<script id="__NEXT_DATA__">`、`window.__NUXT__=` 内嵌 JSON。
  脚本被清理掉之后，正文仍然能还原出来。
- **噪音清理**：站点塞进正文的「请勿开启浏览器阅读模式」「求收藏」「防盗声明」等提示句会按文字
  内容摘掉（CSS 选择器做不到这件事）。
- **按站点定制请求头**：规则里可声明 `referer` / `userAgent`，应付校验来源页或只认移动端 UA 的站点。
- **样式自定义**：字体、字号、行距、页宽、段距、首行缩进、字距、文字/背景色、夜间阅读、
  自定义 CSS，实时生效；可只对当前站点生效，也可全局生效。
- **多标签 / 书签 / 历史**：标签页与阅读状态持久化，关掉 DBX 再打开还在。

## 伪装主界面（老板键）
工作台**默认显示一个看起来完全普通的 SQL 工作台**：连接选择器、数据库下拉、一段内容库巡检
的 SQL、下面是一张结果表格（列名带类型、行号、阅读量、完读率）。界面上不会出现任何「阅读 /
网页 / 小说」字样，窗口标题与状态栏也都是数据库客户端的口吻。

- **右上角齿轮**是唯一入口：打开设置面板。面板里只留两组——**外观**与**切换热键**，
  一眼能看到、也最常用。其余开关都在阅读界面那边设置抽屉的「设置」页签里。
  （原来这里还有一个「进入阅读界面」按钮，已去掉：进阅读界面用热键或工具栏就够了。）
- **界面里的控件是真的能用的**：结果区有筛选框（按关键字过滤行，行数跟着变）、复制、导出 CSV
  （沙箱里没有下载通道，所以是"按 CSV 复制到剪贴板"）；连接 / 数据库下拉切换会有状态反馈；
  `Ctrl/Cmd+Enter` 能触发「运行」。点了没反应的界面反而更可疑，所以这些都不是摆设。
- **热键切换**：默认 `Esc`，可随时在两个界面之间来回切。点设置里的输入框后直接按键即可改绑
  （`Alt+Q`、`Ctrl+Shift+H` 之类都支持），「恢复默认」还原为 `Esc`。
- **外观三选**：日间 / 夜间 / 跟随 DBX。选日间或夜间时插件不再跟随宿主外观，整屏（含伪装层
  与阅读界面）都是你要的那一套。外观与热键在**两个地方都能改**（伪装层的设置面板、阅读界面的
  设置抽屉），改一处两边同步。
- **两个可选开关**（默认都按最不打扰的方式）：
  - 「打开工作台时先显示这个界面」——默认**开**。
  - 「离开工作台时自动显示这个界面」——默认**关**，但**推荐打开**。开启后只要焦点离开工作台
    （切到别的程序、点到 DBX 其它面板），伪装界面立刻盖回来。这一条比热键更可靠：热键本身需要
    焦点，而这条恰好补上了「没有焦点」的场景。
  - 「切回 DBX 时自动显示这个界面」——默认**关**。打开后从别的程序切回 DBX 也会自动盖回。
- **不会抢焦点**：插件只在你按热键切回伪装界面时主动拿一次焦点。点击阅读界面、拖动样式滑块、
  在地址栏输入都不会被抢走。
- **数据是可信的**：表格里的标题取自当前页面真实抓到的章节名 / 图片说明，行数跟着正文量走；
  点「运行」会重跑一次、数字随之变化。同一个网站每次打开看到的是同一批数据，不会跳来跳去。
- 伪装层显示期间，阅读相关的快捷键（`Ctrl+L`、`Ctrl+R`、`Alt+←/→`）一律不响应。

> **关于热键的一个真实限制**：插件跑在沙箱 iframe 里，键盘事件只有在工作台**拥有焦点**时才会
> 送进来。如果你刚在 DBX 左侧连接树或别的面板点过，第一次按键可能收不到——点一下工作台内部
> 即可（正常情况下浏览器会自己把焦点交给 iframe，不需要手动抢）。
>
> **更可靠的做法**是打开「离开工作台时自动显示这个界面」：它不依赖按键，只要焦点一离开就把
> 伪装界面盖回来。热键需要焦点、这条恰好补上没有焦点的场景，两者配合才真正稳。
>
> 彻底解决方案（全局热键）需要宿主开放 `host.registerShortcut` 之类的能力，目前 Host API
> 没有提供，扩展宿主属于 `t8y2/dbx` 的改动范围。

## 自检与静态检查

- **设置 → 设置页签 → 状态自检**：显示宿主存储是否可用（不可用则书架与阅读位置不会保存）、
  书架索引体积（对照宿主 256 KiB/条 的上限）、磁盘上原文的文件数与体积、繁简字库规模、
  站点预设条数。出问题时截一张图就能定位，不用互相猜。
- **`tools/run-tests.ps1`** 现在包含两类 UI 静态检查，专门抓"运行时不报错、但永远不执行"
  的漏接线：
  | 脚本 | 查什么 |
  |---|---|
  | `check-element-ids.mjs` | `$("id")` 是否都有对应元素、有无重复 id |
  | `check-el-refs.mjs` | 每个 `el.xxx` 是否都在元素映射表里声明过 |
  真实收益：`el.styleCustomCss` 从来没被收进映射表，于是自定义 CSS 的语法校验
  **一直是死代码**（第一行就 `return`），而且不报任何错。静态检查第一次跑就抓到了它，
  顺带还抓到一处被粘到别行末尾的 `el.browserLabel`。

  - 自定义 CSS 会**实测是否生效**：写完语法通过后会插入一条探针规则并读回计算样式，
    告诉你"已在本页生效"或"没生效（宿主可能拦了内联样式）"——只报语法对不对是不够的，
    因为选择器写错的规则是**完全静默**的。

## 开发

需要 Node.js 22+、Rust 工具链，以及官方插件 CLI：

```powershell
npm install --global @dbx-app/plugin-cli
cd webview
dbx-plugin dev --path . --port 5190      # 浏览器开发宿主，不需要启动 DBX
dbx-plugin package .                     # 产出 dist/<id>-<version>-<target>.dbxp
```

- SDK（`dbx-plugin-sdk`）不在 crates.io 上，由 CLI 在 `dev` / `package` 时注入 `[patch.crates-io]`，
  所以**请通过 CLI 构建**，不要直接 `cargo build`。确实需要直接用 cargo 时，在自己的
  `~/.cargo/config.toml` 里配置 patch 指向 CLI 包内的 `sdk-root`，不要把本机绝对路径提交进仓库。
- 单元测试与「不启动 DBX 也能跑」的协议冒烟测试：

```powershell
# 一条命令跑完引擎测试 + Sidecar 测试 + 协议冒烟测试
powershell -NoProfile -ExecutionPolicy Bypass -File ..\tools\run-tests.ps1
```

`run-tests.ps1` 会临时生成一个 `[patch.crates-io]` 配置文件（放在系统临时目录，
不写进仓库），指向 CLI 自带的 SDK 源码，所以直接跑 cargo 也不会因为
`dbx-plugin-sdk` 不在 crates.io 上而失败。

站点规则体检（会真实访问各站点，约 40 秒）：

```powershell
node tools\check-presets.mjs webview\backend\target\debug\dbx-plugin-webview.exe --json tools\preset-report.json
```

它按 15 条内置预设各抓一次，输出一张 markdown 表格：命中哪条规则、阅读/整页两种模式各抽到
多少字、图片与章节数、耗时，以及判定（`OK` / `THIN` 站点本该没正文 / `BLOCKED` 被反爬挡 /
`MISMATCH` 命中了别的规则 —— 这条最值得关注 / `ERROR` 传输失败）。改完规则跑一次就知道有没有回归。

繁简映射表由源表生成，改完 `tools/t2s-src/*.txt` 后重新生成并校验：

```powershell
node tools\build-trad2simp.mjs     # 生成 webview\ui\trad2simp.js
node tools\verify-trad2simp.mjs    # 校验结构、冲突与可疑条目
```

## 安全说明

- Sidecar **不是操作系统沙箱**，以当前用户权限运行，签名只证明发布来源。本插件会：
  - 只发起 HTTP(S) 请求（拒绝 `javascript:` / `file:` / `blob:` / 超长 `data:`）；
  - 在返回给 UI 之前删除 `script` / `iframe` / `form` / 事件处理器属性，重写并校验所有 URL，
    白名单化标签与属性，内联样式只保留排版属性；
  - 不把 Cookie、凭据或请求头返回给 UI。
- **实时页面是一个真实的 WebView2**：它直接加载远端站点，登录 cookie 存在插件数据目录的
  `live-browser` profile 里，不会回传给插件 UI，也不会写进宿主 storage。CDP 只在 sidecar
  进程内通过 `CallDevToolsProtocolMethod` 调用，不监听本地调试端口；UI 发来的输入只接受
  鼠标/键盘/文本三类白名单动作。
- 渲染结果仍在插件 iframe 内，受插件自身 CSP 约束；远端页面样式表里的 `url()` 会被改写成绝对地址，
  `@import` 会被丢弃。
- 站点规则里允许保留自定义 CSS 与 `style` 属性，这是为了还原站点排版所需；如果某站点内容不可信，
  请在样式面板里关闭自定义 CSS 或改用整页模式。

## 已知限制

- 纯前端渲染的站点（抖音 / 小红书详情页、知乎回答等）服务端 HTML 里没有正文。插件现在
  对小红书默认走**插件内实时页面**（见下），其它站点也可以点工具栏的「实时页面」或
  「浏览器打开」。
- **插件沙箱内嵌不了外部站点**（实测，非猜测）：插件文档自己的 CSP 是 `frame-src 'self' blob:`，
  真实宿主更严，是 `default-src 'none'`。任何指向站点的 `<iframe>` 都会被浏览器直接拒绝：
  ```
  Framing 'https://www.xiaohongshu.com/' violates the CSP directive: "frame-src 'self' blob:"
  ```
  所以「把原站点 iframe 进 DBX 面板」在插件体系内做不到。**实时页面不是 iframe**：sidecar
  的 WebView2 是独立原生进程，它把渲染后的像素帧交给插件 UI，因此不受宿主 CSP 限制。
- **以下站点服务端拿不到正文**：抖音、红果短剧、微博、知乎、23qb。它们对服务端请求只返回
  验证码中间页 / 访客验证页 / 403。抖音与红果已有预设，能抽到就抽、抽不到走通用兜底；
  要看真实内容用工具栏的「实时页面」。
- **小说站规则只列实测能抽到正文的域名**。判定标准是「在**章节页**用阅读模式抽到正文，并且找到了
  正文容器」——首页有文字量不算通过，因为小说站首页永远是推荐列表。实测结论：
  - 可用（写进 `novel-generic`）：`bqg221.com`、`biquge365.net`、`shuquge.com`，以及类名随机化的
    `taishuaile.com`、`qbtr.org`。
  - **大型平台站的章节页要登录/cookie 才给正文**：阅文系（`hongxiu.com`、`readnovel.com`）、
    纵横（`zongheng.com`）、`17k.com`、起点（`qidian.com`）、晋江（`jjwxc.net`）。服务端只拿到
    推荐位，所以不再列名 —— 想看这些站请用「浏览器打开」。
  - `linovelib.com` 有 Cloudflare 挑战页（返回的是挑战页而非正文）。
  - `dingdian999.com` 可用但正文偏短（约 250 字），保留但预期要放低。
  - 已实测失效并移除：`hetushu` `ptwxz` `ddxs` `5atxt` `xbiquge.bz` `beqege.cc` `69shu`
    `uukanshu` `yikan` `rain8` `dingdiann` `biqu5200` `shu8` `txtnovel` `kanunu8`
    `esjzone` `penana` `qu-la` `bqgui`。
- 首页 / 频道页 / 列表页本身没有正文，抓到的只是一堆链接。插件会识别出「链接墙」并提示换详情页，
  不会把一屏导航链接倒给用户。
- 「用浏览器打开」需要一个已安装的 Chrome 或 Edge，并且不支持 Windows 以外的实现（POSIX 分支留了
  `os.pipe` 版本但未验证）。
- **Chrome 无头渲染模式仍未启用**：Chrome 的 TCP 调试端口在本机被安全策略拦住了 —— 端口方式表现为
  「能监听但连不上」，管道方式表现为 Chrome 不接入。决定性证据是让 Chrome 去访问它**自己**的调试端口：
  ```
  DevTools listening on ws://127.0.0.1:9521/devtools/browser/9a64c8cc-...
  /json/version -> ERROR Failed to fetch      ← Chrome 自己都连不上
  ```
  所以没有交付基于 Chrome 远程 CDP 的「取回渲染后 DOM」功能。
  **插件内实时页面走的是另一条路**：WebView2 的 CDP 在 sidecar 进程内通过
  `CallDevToolsProtocolMethod` 直接调用，不经过 localhost 端口，因此不受这个限制；但它只把
  渲染帧交给 UI，不返回 DOM。
- 站点规则是启发式的，站点改版后可能需要调整 `engine/src/site.rs` 里的选择器。
- 图片由 Sidecar 代理并转成 data URI，因此首屏图片是滚动到附近才加载的；超大图（>4 MB）会被跳过。

## 插件内实时页面（小红书 / 登录 / 评论）

打开 `https://www.xiaohongshu.com/explore`（或点侧栏的小红书预设）时，插件会自动切到实时页面：

- **画面是真实 Chromium 渲染的**，不是抓下来的 HTML，也不是 iframe。sidecar 在屏幕外创建一个
  WebView2 窗口（`WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`，位置 -20000），把它的视口固定为
  1280×900，用 CDP `Page.startScreencast` 取 JPEG 帧，节流到约 12 fps；UI 侧用 `<img>` 显示。
- **点击 / 滚动 / 键盘**：UI 把显示坐标按 letterbox 换算回 1280×900，再通过
  `Input.dispatchMouseEvent` / `Input.dispatchKeyEvent` / `Input.insertText` 发回页面。
  隐藏的 2px `textarea` 承接中文输入法的组合过程，`compositionend` 后用 `insertText` 写入，
  所以中文评论不用切输入方式。
- **登录**：扫码/手机号登录都在实时画面里完成；WebView2 的 user data 目录是
  `<插件数据目录>\live-browser`（例如
  `%APPDATA%\com.dbx.app\plugin-data\com.dbx.webview\live-browser`），登录一次后 cookie 一直在。
  它与「浏览器窗口」用的 Chrome profile 是两套，互不影响。
- **评论**：点开笔记 → 点评论框 → 直接输入（中文走 IME）→ 点发送。评论框、按钮、图片、
  验证码都是页面真实元素，鼠标事件会被 Chrome 正常命中。
- **后退 / 前进 / 刷新**：走 WebView2 自己的历史，UI 的地址栏和标签标题跟随 `liveState` 事件更新。
- **省电**：切到别的标签页、打开伪装界面（Esc）、插件页面不可见时，UI 发 `livePause` 停掉
  screencast；回来时 `liveResume` 继续，不会在后台一直烧 CPU/带宽。
- **失败回退**：WebView2 运行时缺失、启动失败或超时会给出明确错误，并自动回到阅读模式，
  不会留一个永远转圈的面板。

已知取舍：

- 实时页面只有画面，**没有原生文本选择框**；拖选 + Ctrl+C 会转发给页面，但复制结果取决于页面
  自己的剪贴板处理。想拿正文仍可用阅读模式。
- **没有声音**：screencast 只取画面，视频能看但没有音频；需要声音请用「浏览器打开」。
- 帧流是 JPEG，滚动时约 10–12 fps；快速拖动会略慢于原生窗口，这是像素流的固有代价。
- 仅 Windows；依赖 WebView2 Runtime（Windows 11 自带，Windows 10 通常随 Edge 安装，DBX 本身
  也用它）。

**"实时页面什么都点不动"的两个坑（都踩过）**：

1. **IME 输入框会吃掉 mouseup**。为了接中文输入法，UI 里有一个 2×2 的透明 `<textarea>#liveIme`，
   它在 `mousedown` 时被移到光标处并聚焦。如果它参与鼠标命中（`z-index:1` 且没有
   `pointer-events:none`），`mouseup` 就落在它身上——实时页面只收到 `mousePressed`、永远收不到
   `mouseReleased`，于是**页面永远不会产生 click**（表单、登录按钮、链接全部失灵）。
   修法：给 `.live__ime` 加 `pointer-events: none`（不影响键盘/输入法），并且把 `mouseup`
   挂到 `window` 的捕获阶段、用 `liveInput.pressed` 记账后必定补发 `released`。
2. **CDP 输入失败是静默的**。`Input.dispatchMouseEvent` 的返回值以前被 `let _ =` 丢掉，
   真失败时用户只看到"点了没反应"、日志里一片空白。现在失败会打 stderr 并通过
   `webview/liveError` 送到界面上（只报第一次，避免鼠标移动刷屏）。

回归自测用 `tools/live-probe.html`：一个按钮，点一下就把点击次数写进 `document.title`，
配合 `webview/liveEval` 读标题即可确认"点击有没有真的送达页面"。

## 实时画面的流畅度（实测数据）

动画测试页 `tools/live-fps.html`（持续改变画面），统计 6 秒内实际画出的帧数：

| 版本 | 做法 | 采集像素 | 每帧解码 | 实际帧率 |
|---|---|---|---|---|
| 最初 | `img.src = data:` 每帧重设 + 85ms 节流 | 1280×900 | 31.9 ms | **10.3 fps** |
| 只降质量/隔帧（错误方向） | `everyNthFrame: 2` | 1280×900 | — | 6.8 fps（更差） |
| canvas 解码 | + `createImageBitmap`，50ms 节流 | 1280×900 | 31.9 ms | **15.8 fps** |
| **现在** | canvas + **按面板尺寸采集** + 16ms 节流 | 1210×851 | 11–13 ms | **37.8 fps** |

四条结论：

1. **瓶颈是解码，不是传输**。`img.src = "data:image/jpeg;base64,…"` 会把 JPEG 解码压在主线程；
   换成 `atob → Blob → createImageBitmap`（解码在工作线程）+ `drawImage` 之后，收到多少画多少。
2. **解码成本 ≈ 像素数**，这是最大的杠杆：1280×900 每帧 31.9ms，960×675 只要 12.6ms。
   所以采集尺寸由 UI 按面板实际大小给出（`liveOpen.captureWidth/captureHeight`，
   面板 resize 时发 `webview/liveResize`）——屏幕本来就显示不了那么多像素。
3. **节流不是越松越好**：完全不节流时 60 个事件/秒把事件循环压住，单帧解码反而涨到 27ms，
   实际只画出 27 fps。16ms（≈60 上限）实测最好。
4. **换成二进制传输的收益很小**：省掉的是 base64 的 ~25% 体积和 JSON 解析，动不了那 11–13ms 解码，
   乐观估计 +5 fps 左右；真正有效的是第 2 条的采集尺寸。

诊断计数器 `window.__dbxLiveStats`（`received` / `drawn` / `bytes` / `decodeMs` / `decodeCount`）
可以直接读，用来区分"没收到帧""收到了画不出来""解码太慢"。


## 用浏览器窗口打开（需要声音 / 视频时的备选）

Chrome 窗口仍然是「真实渲染」的另一条路（现在不是唯一一条）。沙箱内嵌不了站点，但 Sidecar
是原生进程，可以直接拉起系统上已装的 Chrome / Edge：

- **独立 profile**：`%APPDATA%\com.dbx.app\web-reader-browser-profile`。
  不碰你自己浏览器的登录态、书签、扩展；在这个窗口里登录一次，下次还在。
- **无地址栏窗口**：用 `--app=<url>` 启动，看起来就是个干净的阅读窗口，不是一整个浏览器。
- **阅读样式会跟过去**：当前阅读样式（字体、字号、行高、页宽、配色、段落间距、自定义 CSS）
  会被写进 profile 的 `User Style Sheets/Custom.css`，浏览器原生生效。用自定义样式表而不是 CDP
  注入，是因为它不需要任何远程调试通道 —— 在那些「调试端口被安全策略拦掉」的机器上照样有效。
- 入口有两个：地址栏右边的「浏览器打开」按钮，以及样式面板底部的「浏览器窗口」区块（那里会显示
  找到的浏览器和 profile 路径）。
- 想指定别的浏览器：设置环境变量 `DBX_WEBVIEW_BROWSER` 指向可执行文件。

### 「取回浏览器窗口的当前地址」是怎么做到的

没有 CDP 可用（本插件的目标环境里调试端口与命名管道都可能被安全策略拦掉，见「已知限制」），
但阅读窗口用的是**我们自己的 profile**，它的 `History` 就是一个标准 SQLite 文件。所以 sidecar
直接读文件就够回答"现在在哪一页"，既不需要网络也不需要调试通道。

`engine/src/history.rs` 里是一个**自己实现的最小只读 SQLite 解析器**，而不是引入 `rusqlite`：
只需要「按 rowid 顺序读出 urls 表的 url / title / visit_count / last_visit_time」这一个查询，
而且不引入 C 依赖，交叉编译与打包都更省心。读文件是纯只读操作，绝不写入（浏览器可能正开着这个库）。

覆盖：文件头、table b-tree（叶子页 / 内部页）、溢页链、varint、序列化类型 0–9 与 12、
UTF-8 与 UTF-16 文本。不覆盖：索引、`WITHOUT ROWID`、加密库、尚未合并的 WAL 事务 —— 用不到，
最坏情况是列表少几条最近记录。

两个容易踩的坑，都已在代码里注释：

- **第 1 页的前 100 字节是文件头**，它作为 b-tree 页时页头从偏移 100 开始。漏掉这点会把
  `SQLite format 3` 的首字母当成页类型（实测读到 `0x53`，也就是 `'S'`）。
- `blob` / `real` 这两个类型虽然用不到，但**必须能算对长度**，否则后面的列会全部错位。

正确性用 `tools/history-truth.py`（真正的 `sqlite3` 模块）做基准核对：同一份 Chrome 历史库，
两边读出的行数、URL、标题完全一致。
- 未做视频 / 音频播放：`<video>` / `<audio>` 会被清理掉。
